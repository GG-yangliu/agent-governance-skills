# 给不看命令行的人交付可双击工具（Windows）

适用：用户不读命令行、也不打算学，但需要"自己双击一下就能跑"（只读核对、刷新、出报告）。
交付物＝**脚本 + 模板/配置 + 结果文件 + 一份零基础说明**，且现场跑通才算完成。

## 工作流

1. **开工前定三件事。**（a）放哪：业务目录，用户找得到、能备份，不放系统临时目录——脚本、模板、结果文件、说明同一个文件夹。（b）碰什么：默认只读；真写单独做一个入口，并写明改什么。（c）要不要定时：用户拍板。"每次都要提醒我"是抱怨不是批准——先交"手动双击 + 结果落文件"，定时另外提、等点头。定时还要通知的，必须投到网关能到的渠道，本地会话收不到。
2. **`.bat` 一行只干一件事**：找 python → 调 python → `pause`。所有中文提示、遮码输入、结论都放 Python（3.6+ 走 `WriteConsoleW`，任何代码页都能显示）。
3. **定位靠文件、不靠调用者。** `pushd "%~dp0"` 定目录，`"%~dp0tool.py"` 定脚本，整个文件夹可以搬走。解释器写绝对路径并三级回退——`<venv-python>` → 办公软件自带的解释器（`<office-suite>\program\python.exe`）→ PATH 里的 `python`。别指望 PATH 有 python：普通 cmd 里 `where python` 返回空，bat 第一句就退出，窗口一闪而过。
4. **结果在 Python 里 Tee 到文件**——真 stdout + 结果文件，追加写，每次开头一行时间戳和命令；并且**退出码要如实**：判"不可写"就 return 1，让 bat 能分流。
5. **写说明、体检 bat、读回结果，再教第一次打开**（见下）。验收是交付的一部分；另留一个只读入口，用户怀疑数字时能自己核。

## 必查项

一条不过就别叫交付完成。示例只是示意，不限定检查范围。

`.bat` 字节层：

- **用机器体检，不用肉眼**：无 127 以上字节、每行 CRLF、没有多行括号块、引用的解释器真存在——任一项不过就 exit 1。
- **每行必须 CRLF。** 纯 LF 会让 cmd 把中文 `echo` 拆断，报"不是内部或外部命令"、后半句当命令跑；还会让 `cd /d "<目录>"` 静默失效，子进程从调用者当前目录跑，python 报打不开文件。先数 `data.count(b"\r\n")` 是否等于行数再怀疑别的：`p.write_bytes(text.replace("\n","\r\n").encode("utf-8"))`。
- **说"纯英文 bat"就得断言**：`sum(1 for b in open(p,'rb').read() if b>127) == 0`。cmd 按字节偏移读批处理，一个多字节字符会把它后面全部读错位，出现 `fined`、`defined`、`]` 这类碎片，python 只收到半个参数（`setpass` 变成 `set`）。
- **首选 bat 里一个中文都没有**——三行就够；`echo` 行也不要用全角括号或全角冒号堆叠（要解释就用短句）。实测症状：双击、输密码、回车，窗口立刻消失，用户说"闪退"，其实是脚本走到结尾了；凡在"按任意键"之前就没了，先怀疑 bat 的编码与写法，不要怀疑业务逻辑。中文参数也不要经 shell 拼给子进程，用 UTF-8 文件配 `@./args.json`／`@./args.md` 传。
- **非要在 bat 里写中文**：中文 Windows（cp936）用 GBK 落盘（`text.encode("cp936")`）配 `chcp 936`，输出用 `iconv -f cp936 -t utf-8` 读回。UTF-8 配 `chcp 65001` 实测会把某条中文 `echo` 拆半，报 `'xx' is not recognized`，其余几条却正常。中文 `echo` + `chcp 936` + CRLF + 全部单行（含 `for /f` 取最新文件、`start "" notepad` 打开）可用；代价是控制台锁 936，Python 子进程要 `PYTHONIOENCODING=gbk`，否则屏幕上的中文是乱码（文件本身是对的）。
- **bat 里不要用括号块。** `if not defined X ( … )`、`if errorlevel 1 ( … pause … )` 只要再叠一个异常，cmd 就把块读错位、把后面的行当命令跑。用连续单行赋值代替，宁可多写两行：

```bat
@echo off
cd /d "%~dp0"
set "PYEXE=<venv-python>"
if not exist "%PYEXE%" set "PYEXE=<office-suite>\program\python.exe"
if not exist "%PYEXE%" set "PYEXE=python"
"%PYEXE%" "%~dp0tool.py"
pause
```

- **改已存在的 `.bat` 不要做字节级局部替换。** 路径里的 `\02`、`\10`、`\0` 会被当八进制转义：`<盘符>\02-project` 落盘变 `<盘符>\x02-project`，`backup_all.py` 变 `\x08ackup_all.py`；文件在、脚本找不到，而且第二次 patch 还会"成功替换"，越修越坏。要改就整篇重建（`"\r\n".join(lines).encode("utf-8")` + `write_bytes`），落盘后断言哨兵串（`b"backup_all.py" in data`）并 decode 读回。写进文件的路径字面量一律 raw string——普通字符串里 `\releases`、`\0_tools`、`\AI` 会变转义，`releases` 落成 `eleases` 或凭空断行；patch 工具同样解释 `\r`，改完必读回那一行。

用户自己输一次的密钥——不许进聊天，不许落明文：

- **首选** `ctypes` 直接调 Windows DPAPI（`CryptProtectData`／`CryptUnprotectData`）配 `getpass`：没有 PowerShell 引号转义、没有中文传参、没有代码页坑。非用 PowerShell 不可时：`Read-Host -AsSecureString`（不回显）+ `ConvertFrom-SecureString` 存文件——DPAPI，只有本机本用户能解；提示里必须写"输入时不显示是正常的"，否则用户以为键盘坏了。
- **传给 powershell 的片段保持纯 ASCII。** 中文经 cmd → powershell 会按代码页拆坏（连 `ConvertFrom-SecureString` 都报参数绑定失败）。中文放 bat 的 `echo` 行，`Read-Host` 的 prompt 只写 `Password (hidden): `。含中文的 `.ps1` 必须存 UTF-8 带 BOM 再用 `-File` 跑，无 BOM 会被当 ANSI 读，症状像参数类型错。
- **先做加解密往返测试，读回来必须 `.Trim()`。** `ConvertFrom-SecureString` 只接 SecureString，喂普通字符串报 `InputObjectNotBound`：用 `ConvertTo-SecureString 'x' -AsPlainText -Force | ConvertFrom-SecureString | Set-Content $f -Encoding ASCII`。读用 `(Get-Content -Raw $f).Trim() | ConvertFrom-SecureString`（尾部换行会报"输入字符串的格式不正确"）；取明文用 `[Runtime.InteropServices.Marshal]::PtrToStringAuto([Runtime.InteropServices.Marshal]::SecureStringToBSTR($s))`。
- **调用方用 `subprocess.run(..., capture_output=True)`** 取字节再 `decode('utf-8','replace')`，失败回退 `mbcs`；`text=True` 在中文 Windows 上因 stderr 是 cp936 直接抛 `UnicodeDecodeError`。**`ConvertFrom-SecureString` 存的是 UTF-16LE 十六进制**，用 UTF-8 解会得到两倍长度、夹 `\x00` 的串（17 位密码解出"34 位"）；按 utf-8 → utf-16-le 逐个试、取没有 `\x00` 的那个，同一份文件可能同时存在二进制 DPAPI 块与十六进制，先试二进制再 `bytes.fromhex()`。
- **`getpass` 只在真控制台里正常**；stdin 被重定向（管道、自动化测试）会挂住不返回，看起来像脚本卡死。留一个 stdin 钩子（环境变量开关）给测试，真实双击走 `getpass`。
- **没凭据时给可执行的下一步，不要报错**："还没有设置密码。请双击：<设置密码.bat>"。**换了账号必须先删旧凭据再让用户重输**：同一个文件不会自动失效，新账号拿旧密码认证，报错和"密码错"一模一样，会白绕几轮。动作顺序：改账号/地址 → 删凭据 → 双击设置密码 → 双击复验。
- **认证失败先分层，不要急着让用户改密码。** 先看网页能不能登：网页能登、各协议在自己端口全被拒、密码形态也正常 → 卡在客户端凭据那一层（客户端专用密码、域策略），重置密码无用，最快的路是新建账号或生成客户端专用密码。**验证按阶梯走，全程不需要真密码**：端口连通 → 假值跑一遍加解密往返 → 用假密码真认证一次，拿到"认证失败"就证明链路全通、只差真密码；测完删掉假凭据。

会写数据的入口，永远两步：

1. **第一步只跑练习**：全部校验跑完，打出"本次将写 N 条／库里现有 M 条／分几批"和一行结论（`[可写]`／`[不可写]`）。
2. **第二步停下来，要用户亲口输一个词**（如 `确认写入`）才执行 `--commit`；输别的任何内容一律放弃，库里一条不写。比 `y/n` 强：误按回车不会写，用户也看得出这一步是"真的写"。
3. **退出码如实**：判"不可写"就 return 1，bat 用 `if errorlevel 1 goto notok` 分流。脚本恒返回 0，bat 就分不出"跑完了"和"过不了"，用户看到的是"它说写完了、其实没写"。
4. **每次跑完自动落报告，真写那份带全部 record_id**——那是回滚依据，也是"到底写了什么"的证据；只打在窗口里的 record_id 等于没有。
5. **入口两到三个，命名统一**（`双击_<动作>.bat`）：体检（只读）／批量写（两步）／单条补录。多于三个用户就开始猜。

结果要落文件：

- **用户按一次回车窗口就关，屏幕上的结果随之消失**——最常被投诉的"不行"。在 Python 里做 Tee（真 stdout + 结果文件）；bat 里 `> 文件` 更差，它会把遮码输入的提示一起吞掉，用户对着空窗口不知道该干嘛。日志里只有时间戳头、没有结论行＝子进程输出没接上：收尾时 `type` 一遍日志，必须看到结论行（条数、结论），只有表头就算失败；修法是用 Tee，不是给子进程拼 `>>文件 2>&1`。
- **追加而不是覆盖**，每次开头写时间戳和命令，事后能看出哪一次跑出了什么。**结果目录加进 `.gitignore`**：双击一次一份报告，业务目录若是 git 仓库，`git status` 天天多出一堆未跟踪文件、把"改了哪些"冲成一团——报告仍在磁盘上，只是不进版本库。
- **失败分支要有真 stderr。** 只 echo 一句"失败：可能没联网"、屏幕上一个 traceback 都没有，用户没法反馈、你下一轮什么都查不到。写 `"%PY%" tool.py 2>"%TEMP%\tool_err.txt"`，`errorlevel 1` 时 `type` 出来并追加进结果日志。特别注意 `if not exist "%PY%" set "PY=python"` 这种回退——命中 WindowsApps 的假 python 时是非零退出且零输出。
- **控制台两句话都必写**：开头先说"最后那句『请按任意键继续』是让你看完再关，按回车关掉属正常结束"；末尾只说"窗口关掉不影响结果，以后双击最近一次结果文件就行"。结果正文写成**给人看的小表 + 一句结论**（"4 个订单全部齐，没有缺的"），不要只给 `TODO_COUNT=0`。

**说明文件（`使用说明*.md`）必须有的节**：这是什么／双击哪个文件／会看到什么／它**不会**做什么（红线）／报错了怎么办、截图发给谁／**命令在哪里输**（哪个文件夹、右键哪个入口开终端）／本文件夹在哪／变更记录。"命令在哪输"是必填项，哪怕用户永远不会敲。再加一节**"它怎么保证不出错"**（3–5 句人话）：改的范围（只换指定那一段，或只读不改）、改前改后各做了什么校验（数出现次数、改完读回、逐行比对）、留痕在哪（日志、报告目录）——隔几周回来问"到底怎么实现的"，说明上一轮没讲清机制。

**解释一个用户看不见的工具**（存档提交、后台任务、定时器）——给三件事，不是原理：

1. **谁在什么时候触发它。** 别写"已实现自动化"，那听起来像电脑自己会发现改动。写：没有常驻监测，是我改完主动喊它一声，这一步你不用管。
2. **想自己看时点哪里。** 给一个**只读双击入口**把 CLI 翻成中文 txt：`status/log/diff` → "还没存档的改动清单（标新增/修改/删除）／最近 N 次存档（时间+说明）／改动规模（每文件加几行减几行）"，同时落 `output\` 供事后翻。只读可以随便点；写、回退、删除永远不给按钮。
3. **用户和"命令行里那个东西"是什么关系。** 一句话点破：命令是手动挡、双击入口是自动挡、发动机是同一个 exe（写上版本号）。
- **配套必写**：红线单独成节（`reset`／`checkout`／`clean`、覆盖、删除——逐条"不要自己敲，找我"，并说明未存档改动会直接消失）；**它不是备份**（本机仓库 ≠ 异地副本，防丢是另一套）。说明文件与其它零基础说明放同一位置。

**常驻终端界面（tmux 类）的交付，多加三点**：

- bat 里不要直接跑 exe，用 `start "" wt.exe -w -1 new-tab --title "X" -d "<起始目录>" "<exe>"`。Windows Terminal 的文字、缩放、鼠标事件才正常；旧控制台会花屏、丢鼠标事件。
- 再建一个桌面 `.lnk` 指向 `.bat`（PowerShell `WScript.Shell.CreateShortcut`，`IconLocation` 用 exe，`WorkingDirectory` 用脚本目录）；中文名写进 UTF-8 BOM 的 `.ps1` 再用 `-File` 跑，别经 `-Command` 传中文。
- 验证：`MSYS_NO_PATHCONV=1 cmd /c "x.bat"` 跑一次，再 PowerShell `CopyFromScreen` 截全屏并真的看图——TUI 没法靠退出码判断。

**改已交出去的工具**：

- **先留改前版本再改原文件。** 这类目录不是 git 仓库，`write_file` 覆盖就再也拿不回来（`.pyc` 反读不回来）：复制到 `_备份/<脚本>_v<n>_<日期>.py`，并在说明里写"v1 已并入 v2"。**改完必须真跑一次**，lint 通过不算证据：读最新结果文件的结论行，再看具体表；首跑出现"故障 1 行"，先怀疑自己的过滤/方向逻辑，再怀疑数据。
- **报告类脚本的列名不能随数据变。** 表头取 `rows[0].keys()`，列名逐行变化（一行 `Σ 支出流水`、下一行 `Σ 收入流水`）就直接 `KeyError`。把方向这类维度单独成一列（`方向`：支出/收入），列名固定。
- **报告里凡属推断的，只能写"候选原因（待确认）"**——例："疑汇率折算差：该合同流水全为外币，按核算汇率折人民币后与合同额不同，需财务确认是汇差而非欠款"。判定列仍写"未解释差异"；工具替业务定性，人就会把推断当事实。

**教第一次打开**——"不会用啊"这句是固定环节，不是意外：

- **先读用户屏幕上的真实状态再开口**：截图，或调平台自己的状态接口，把"现在屏幕上是什么"念出来；照着文档讲没用，用户只能看懂自己屏幕上的东西。**只给三个动作**，加一句"这看着像坏了、其实正常"——空界面、空提示符最容易让人以为工具坏了。**常驻类工具一定要说清"关窗口 ≠ 停进程"**，不停会后台烧额度，这是最容易火大的坑。
- **上手说明写进同一份 `使用说明*.md` 开头**（"三分钟上手"），不另开新文档；额外只发短消息，不贴长手册。**在用户窗口里现场摆一个可操作的实例**（分一格、起一个 worker）再指着讲，效果好于讲解——但别替用户做安全类决定（信任目录、授权、登录）。

## 示例

只作示意，落地时换成你自己业务的文件、名称与数字。

- 贸易：`双击_核对订单.bat` 把 `2026-11-12 09:14 | 18 单 | 2 单缺 | 其余齐全` 追加进最近结果文件，时间戳头在上一行，没有只有机器才读的字段。
- 物流：一个只读入口列出"还没装柜的柜号（标新增/修改/删除）"，并落 `output\` 备份，没有任何写按钮。
- CRM：两步写入口打出"将写 42 条／现有 380 条／分 3 批"和 `[可写]`，再要求输入 `确认写入`；报告里保留全部记录 id。
- 零售：bat 只有三行（`pushd`、调 python、`pause`），提示全在 Python 里，所以不依赖控制台代码页；任何行业都用下面这套模拟——中文名先复制成 ASCII 名，绝不用 `sed` 生成：

```python
shutil.copy("check_tool.bat", "_t.bat")
r = subprocess.run(["cmd", "/c", "_t.bat"], capture_output=True, text=True, encoding="utf-8", errors="replace", input="\n")
```

## 坑

- **中文 Windows 上 UTF-8 配 `chcp 65001`**：某条中文 `echo` 被拆半，其余几条正常、就一条报 `']' is not recognized`，很像工具抽风。改用 GBK + CRLF。
- **纯 LF 文件**，或"英文 bat"里漏进**一个多字节字节**：`cd /d` 静默不生效、读取偏移错位，python 报"打不开文件"——看着像路径写错，其实是行尾/编码。
- **括号块再叠一个异常**就把块变成命令；一个字节错位是同样的破坏。
- **从 git-bash 里 `cmd //c "x.bat"`** 常常开一个交互 cmd、把参数丢掉、只输出版权横幅，中文文件名还可能匹配不上；用 Python 跑 ASCII 副本，且绝不用 `sed` 生成副本（它把 CRLF 改成 LF，跑出来的症状和编码写坏一模一样）。
- **bat 恒退出 0、调度状态显示 "ok"、装在 WindowsApps 路径上的假 python**：三种都在什么都没干时报成功。判据是结果日志里的结论行，不是状态。
- **拿管道里抓到的输出当判据**：GBK 的 bat 输出和 UTF-8 的 Python 输出混在一个管道里必然花，`iconv` 只能解一半。看三样：退出码、产物是否生成、产物里的结论行。
- **用 `>` 取代 Tee** 会把遮码提示一起吞掉、**只有表头的日志**什么也证明不了；**字节级改路径**（`\02`、`\0`、`\10`）静默改写路径且下次 patch 还"成功"；**表头按第 0 行取列名**，数据一混两类行就崩。
- **凭据链路的四个坑**：`text=True` 或按 UTF-8 解 PowerShell 输出会抛错或长度翻倍；`ConvertFrom-SecureString` 喂普通字符串报参数绑定失败；换账号后留着旧凭据＝复现"密码错"；`getpass` 在 stdin 被重定向时挂住，而挂住报到你这里就是"卡死了"。

## 自检
