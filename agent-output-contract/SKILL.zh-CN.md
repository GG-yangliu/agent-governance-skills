# AI 输出契约

给"读数据、给答案"的 AI 定契约，让源覆盖范围、不确定之处、失败表现都看得见。

## 流程

1. **说清任务和读者：** 回答什么问题、给谁看、支撑什么决定。
2. **列出允许使用的源。** 每个源写：作用、查询标识、字段、时效和访问限制。权威源与汇总/缓存分开。
3. **定证据要求。** 每个有分量的结论都要附记录号、链接、时间戳或字段。标识只能从源数据复制，不许编造，不许用"看起来合理"的内容填空。查不到就说查不到。
4. **定义失败状态：** 源读不到、无匹配、记录矛盾、数据过期、必填字段空白。含糊且影响答案时要反问；属于业务方拍板的事，停住并给条件结论。
5. **选输出格式。** 给人看：定章节。给机器用：定字段、类型、必填项、错误形式，不混聊天措辞。
6. **划动作边界。** 只读，或某个具体动作。改记录、发消息、影响外部系统的动作须单独授权，并在输出中写明。
7. **测六种情形：** 正常、无结果、缺字段、记录冲突、源读取失败、问题含糊。内容与失败行为分开验。

## 必查项

这些查的是「答案本身」，不是数据结构。规则通用，方括号里只是某一个行业的例子，落地时换成你自己的。

- **单位和口径没写。** 金额没有币种与量纲、也没说毛额还是净额，就不可比；源里没写就写"口径未标明"。【贸易：合同金额写 2,150,000，既无币种也无含税口径】
- **近似值被当成确定数。** 单列出来，不要混进合计当精确值。【物流：数量格里写"约20"】
- **状态说已完成，但证据缺失。** 两边并列，标为冲突。【标了已发货，运单号一栏是空的】
- **同一实体多种写法。** 说清哪些行匹配、哪些没匹配。【CRM：Acme Ltd / Acme / ACME Limited 被当成三个客户】

## 坑

- **"没有记录"和"查询失败"是两个答案。** 把工具报错说成空结果，等于谎称查过。
- **分页和限流**会让前 N 条被当成全量。写明取到多少条、总数（若知道）。
- **静默兜底**（默认值、推断分类、假设）必须标为推断。时效重要时先看缓存和汇总的时间戳。

## 自检

- 每个有分量的结论都能追到凭据，或已标为推断。
- 查询失败报成失败，没有说成“没有数据”。
- 结果依赖完整性处，写明了取回行数和限制。
