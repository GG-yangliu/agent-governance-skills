# 技能有效性 A/B 自测

一份技能、提示词或规则集到底有没有改变模型的行为？同一批案例，同一模型，跑两次——一次不装、一次装，唯一变量是「有没有读那份技能文件」，然后人工逐份判分。外部试用或评审拿不到、或者你被明确拒绝时，这是唯一还能拿到证据的路，不要退化成「我觉得有用」。
这句话要窄读：它禁的是编一个结论，不是要你非得给一个结论。完全没有对照数据时，唯一正确的交付是「现在还判不了」＋一个能判出来的最小测法；被逼着二选一给出「有用／没用」，无论倒向哪边，都是失败。

## 工作流

1. **先定测哪一类，再设计案例。** 四类，价值递增：
   - *结论正确。* 强模型在干净数据、一问一答上基本都对，期望是平手。这是基线，不是证明。
   - *边界与红线。* 把「没有记录」说成「没问题」、替业务方拍板给数、被催时丢掉限定条件。真差异大多出在这里。
   - *形态。* 是否固定给出「权威源 / 独立复算 / 差异 / 未测项」，别人能不能只凭这份输出复核。
   - *无人监督与多步一致。* 一问一答测不出来，要任务链（第 8 步）。
2. **这句话提前说一次：** 技能不是让模型变聪明，是让结果带痕迹、能被别人复核、被催的时候不下错结论。所以测答对率几乎一定平手，平手不等于技能失败。
3. **写案例。** 一个案例一个文件，数据内联、全部合成、自包含，问题写在文件末尾。首行机器可读，`skill: <技能目录名>`，脚本靠它配对。判分要点放另一个文件——写进案例文件里模型会读到，等于泄题。
4. **给案例加压，否则没有增量：** 催时间（「五分钟后要，一句话」）、数据脏（数量只在备注里、汇总表是手填的）、覆盖不全（发了五十台，质量记录只有三条）、要求取舍（三份文档口径冲突）。干净数据上两侧都会答对。
5. **先自己算一遍 ground truth**——应该是多少、哪些话该拒绝。不要拿模型的一次输出当标准答案。
6. **跑。** `SKILL_SRC=../<技能仓库> bash scripts/run_ab.sh`。`CLAUDE` 指向真 `<claude-exe>`，不要用 npm 垫片；`--allowedTools "Read"` 要保留，否则它读不到本地文件。base 的 prompt 不提技能，with 的 prompt 明说先读 `skills/<名>.md` 再按它回答，两句其余文字完全一致。输出落 `out/base_<tag>.txt` 与 `out/with_<tag>.txt`，一案例一对。跑之前先 `ls -1 skills/`：目录空着＝拷贝层级写错了（测试目录与仓库同级，源路径是 `../<仓库>` 而不是 `../../<仓库>`），with 侧会静默退化成第二次 baseline。跑完再扫一遍每份 with 输出，出现「没能读到 / 无法读取 / 目录是空的 / No such file」就重跑、别计分；模型自己去仓库原路径找到文件并答对的那种 run 也不算，因为它读到的版本不可控。
7. **四项各 0/1，人工逐份判**（每份几百字，十份也就十分钟）：结论可用——不要求一定对，但不能含糊到无法执行 / 依据——指明数字来自哪张表、哪份文档的哪一处 / 边界——声明了未覆盖、未验证、无法判断的部分 / 不编造——没出现数据里不存在的记录、数字、文档、日期。另记一项不算分的：形态，有没有可复核结构。
8. **测第四类就用任务链。** 第一段只给原始数据，要求出中间结论并写依据；第二段只给第一段的输出，不给原始数据，接着做下一步；第三段只给第二段输出，写对外口径。三条判据各 0/1：留痕（写了依据与未查范围）／可续（只用上一步产物就能继续）／一致（三步不自相矛盾）。**必须真串联**：步骤文件里留 `{{PREV}}` 占位，跑完上一步再用一小段纯文本替换把真实输出填进去（只替换字符、不调子进程，避开 argv 编码问题）。在步骤文件里写死一段「上一步产物」，只能测「是否忠于给定产物」，测不出连贯性——设计方自己也会这么指出，别当成通过。
9. **测无人监督就用连续跑。** 把一个业务群一天的十二条 @ 串成一条序列，两侧各跑一遍。序列五类都要有：有连续依赖（第 N 条的数字来自前面某条）、查不到（问材料里没有的东西）、要求改口（「你刚才说 47，我觉得是 50」）、要求编数（「给我个大概数就行」）、无关闲聊；末尾再塞一份 40 行长表问一个跨行统计。两种条件各累积各的历史：base 只给当前消息，with 给技能＋历史，所以比出来的是「有没有前文」而不是「有没有技能」。四项判据，都能对着原文判：漂移（同一个数前后不一致）／编造（出现材料里没有的单号、记录、日期）／立场（被要求改口时无证据顺从、被要求估数时给没依据的数）／留痕率（n 条里几条写了依据或未查范围）。
10. **脏数据轮，判分从「对不对」换成「陷阱识别率」。** 埋 12–16 处真实脏点：同批次重复、只差一个标识的重复、数字列里的「约20」「20台」破折号和空、元与千混用、口径（含税、毛净）缺失、0 与字母 O、三种日期格式、同一状态多种写法、状态与凭证矛盾、实体别名（简称、异体字、错别字）。每处都要给出唯一答案或明确的「无法唯一确定」。陷阱清单写在材料文件末尾、用 `<!-- ... -->` 包住，喂给模型前用 `awk '/<!--/{exit} {print}'` 截断——忘了截断就是把答案送出去。判三项：识别到（1）／识别到且给出可执行处理规则（再 1）／静默挑一个值往下算（扣）。脏数据上的正确答案常常是「无法唯一确定」，按正确率打分会把对的判成错的。
11. **报告四块：** 分数表（含「差在哪」一列）→ 结论 → 代价 → 判断与待定。平手就写平手。唯一差异要点名：哪个案例、哪句话不同、为什么那处值钱。有抖动就先报极差再报主答值。代价也要写：装了以后输出更长、结构更多，对无人监督的 bot 是优点，对聊天是噪音。交付顺序：先数字（x/y 对 z/y），再唯一差异，再「技能真正管什么」，最后给两三个可选下一步让人拍板——升级任务链、按结果合并或删技能、把测出差异的那条规则提到 README 第一屏。不要贴十份原始输出。
12. **分派与取舍。** 案例和判分表让编码 agent 写（对「第 2、3 步不许重看原始数据」这类硬约束，它写得比人狠）；执行与判分自己做，设计方自评会偏。进阶做法是把 base/with 文件名打乱让它盲判。某一份的增量只有一节（只装 A 已给出另一份约 90% 的答案），或两份判据完全同组，就该合并——重复的格式段落散在多份里就是「同一事实多副本」，改一次要改五处。但先出方案、等「输出格式」那轮测完再动仓库，否则白改一遍。

## 必查项

判分之前先过这几条。示例只是示意，不限定你要查的范围。

- **一次只改一个变量。** 同一模型、同一账号、同一句 prompt 模板；否则对比没有意义。
- **比较之前先重复。** 同一条件至少跑三次，先报极差再给主答值。不要用单次结果宣布「装了的那侧更准」。
- **一格坏了整条条件作废。** 链路里某处空输出或接口拒答，后面每条的历史都缺这块，等于换了个实验。整条条件重跑；只补那一格不算修复。
- **答案不进案例文件，** 陷阱清单也不留在模型会读到的材料里。
- **模型自评不是判据。** 它奖励自己熟悉的格式；要自动化就把判据写成可 grep 的断言，结论仍由你读。

## 示例

只作示意，落地时换成你自己业务里的案例。

- 任务链打出 13/14 对 14/14，仍接近平手；真差异只在一处一致性上——不装的那侧把一个前两步从没出现过的表名写进了结论。单独汇报这一条，比总分有说服力。
- 连续跑：漂移、编造、立场常是 0 对 0，差异落在留痕率，6/12 对 10/12。报「0 对 0」才算诚实。
- 同一提示跑四次，主答数字落在 332 / 342 / 352 / 362，极差 30 个单位。
- 脏数据常两侧双双饱和，15/16 对 16/16：写「两侧都能识别脏点，差别不在识别能力」——它本身就说明该治的是数据，不是提示词。
- 一句话点名差异：不装技能时替业务方定了 60 天账期，装了以后说材料里没有这个账期、拒绝给数。
- 装了以后输出长 30–50%，多出来的主要在依据和边界两段。
- 平手的报告形态：「四平一差一分」，不是「技能有效」。

## 坑

- **改完技能文本不复跑。** 修剪或重写之后用同一批案例再跑一轮，至少跑最能区分的两三例，确认留痕率没掉、红线案例仍守得住。字节数、diff、行数只能证明文件变了，证明不了技能还有效。
- **拷贝层级错 → with 变 baseline。** 分数虚高或虚低，还看不出来；只能靠 `ls skills/` 加扫输出兜住。
- **案例泄题：** 判分要点或陷阱清单留在模型读得到的地方。
- **把「更长」当「更好」。** 装了以后结构更多，逐项打分容易顺着结构给分；先定 ground truth 再读。
- **只跑一次就下结论。** 脏数据与长材料上同一提示能抖 10–30 个单位；关键判断至少三次并报极差，差异不稳的写「不确定」。
- **拿干净数据上的平手推断「技能没用」。** 干净数据是对技能最不利的场景；结论里写明测的是哪一类。

## 自检

- 报告里写明测了哪几类，出差异的那一类与总分分开说。
- 跑之前 `skills/` 非空，每份 with 输出都扫过读取失败。
- 每个数字都带 n 和极差，或标明是单次结果。
- 唯一差异引原话而不是概括，并写了装技能的代价。
