# 外部模型评审 / 会商（非交互，结果落文件）

手上有一个方案、一份文档改写、一个架构决定，想再要一两份**独立意见**——挑毛病，不是让对方重写。等结论的人不会开终端，也不会在场盯。

和编码委派类技能的分工：那些讲怎么把实现活交出去；本技能只管**一次性参谋**——发一份自包含简报，收一段结构化意见，然后自己逐条核实。

## 工作流

1. **先搭一个目录。** 简报、真实文件的副本、两份输出放同一个目录，`cd` 进去再启动。对方读不到的东西，对它等于不存在。
2. **两个评审器并行跑**——一个前台、一个后台。互不阻塞，后台那几分钟正好用来读前台的结果并开始核实。
3. **指令写成一句话**，装三件事：让对方自己去读简报文件（长文不进 argv）；只评审不重写（否则拿回一份新方案，不是判断）；写明输出格式和行数上限（否则回来一大篇没人看）。
4. **`briefing.md` 必须自包含。** 对方不知道任何上下文，缺一块答案就飘到别的问题上。七节：
   - **环境**——这是什么系统、真值在哪、有哪些载体（数据库／文档／脚本）、谁在维护。
   - **现象（带数字）**——这次为什么要讨论。写**实测**数字（"改一处走了 13 类、20 多个位置"），不写"感觉容易漏"。
   - **已经发生的漏项**——具体到哪一处、怎么发现的。真实事故有说服力，假设没有。
   - **根因**——归纳成几类：同一事实多副本、同构多副本、散落引用、人工贴页。
   - **候选方案 + 各自的代价与局限**——并给出你自己的排序建议。
   - **我列的检查清单**——逐条编号，并请它重点看这一节；增量就在这里。
   - **要它做什么**——四问固定：我漏了哪些检查项、各方案的坑、只能选一个选哪个、有没有更简单的做法被我忽略。**再补一句明确允许"少发／不发／这个位置空着"**：不写这个出口它会为填满名额凑数；实测最值钱的一条就是"第三个位置建议空着，改去给已发的补一节"。
5. **被审对象是规则／提示词文本而不是方案？** 要问的变成"哪一句会让它在真实对话里出错"，不是"选哪个"。四处调整：第 2–4 节换成真事故清单，带编号带数量（编了不存在的工单号、把 JSON 原样贴进对话、自信地答错、删一份记录连带清空 8 条）——没有事故支撑的条款会被建议删掉，而且常常劝对；把平台约束写进简报（markdown 会被渲染成字面量所以不能用表格／代码块、提示词要粘进第三方控制台会被截断被长文稀释、机器人只能读不能写、没有脚本能力）；把自己的疑点单列一节，标题写"你可以直接驳我"；最后一段必须答"如果只能改三处，改哪三处"，强制排序，否则回来 15 条没重点。
   - 事实快照要**最小**：被审文档点名的表，逐表只取表头行（表 id／记录数／字段数）＋字段表，标快照日期，单独一个小文件。上百 KB 的结构说明整本塞进去读不完，反而读错。
6. **被审对象是候选清单**（要删的字段、要合并的条目、要退的资产）？简报必须带三样：编号化的候选表（带继承／引用血缘列）、全量血缘或引用导出（JSON 也行，告诉它只需查指定编号那几行）、你查不了的位置有哪些。要求它**按编号判三档**（确认可做／建议保留／需人工确认）＋末尾"只能做 10 项先做哪 10 项"。没编号的意见回来既无法逐条落地，也无法逐条拒。
7. **被审对象是线上仓库／线上产物？** 让它读线上真实内容，不是你抄给它的副本或你的转述：只有真读到，才能发现"我改完了"和"线上还是旧的"之间的差。放开网络工具（`--allowedTools "Read,WebFetch,Bash(curl *)"`），只给读权限它看不到线上，会凭简报虚构"已核对"。简报里同时给 raw 地址、API 目录树地址，并写一句"以线上为准，本地副本仅供参考"。回来先看它引用了哪些路径——只拿到"一切正常"而没有任何路径引用的，等于没看。
   - 验收它的意见也要读线上，而且不用 raw：CDN 缓存刚推完还会给旧字节，一次"推送失败"就是这么误判的。判据用 `git show origin/main:<path>` 或 API blob，raw 只给人看。
8. **设计与执行必须切开**：让它设计考题又让它打分，等于自评。

| 交给外部模型 | 留给自己 |
|---|---|
| 设计考核式用例，定硬约束（"第 2、3 步不许重看原始数据，只给上一步产物"） | 执行：真跑 CLI、盯日志、取产物 |
| 判据写到能对着原文判（"什么算违规"），而不是"质量好" | 判分：自己读全部输出，设计方不打分 |
| 它自己的数字先自己复算再报 | 判断优先级、决定做什么 |
| 主动报自己方法的漏洞（"base 不带历史不公平"，并加了开关） | 对外文档与汇报 |
| 写脚本骨架、盲判协议、打乱流程 | 对外副作用：发布、上云、改仓库 |

9. **比较两个版本时跑盲判协议**：产物按 `out/<条件>_<序号>.txt` 生成，判分前重命名为 `S01…S24`（映射表单独存），判完还原。设计方只看编号。
10. **收口逐条判，不照抄。** 每条标**成立／打折扣／不成立**：成立 → 当场改方案或加进检查表，并写明"它提的 X 我采纳了"；打折扣 → 说清为什么（全文正则抽数字会把告警淹没，改成只对已知位置做结构化断言）；不成立 → 直说，并给出依据（实测过的行为）。**两方独立撞到同一条**的意见可信度最高。任一方提的"更简单做法"往往比它对你方案的批评更值钱，单独拎出来汇报。
11. **冲突要裁。** 一方说这串枚举该整段移出、另一方说它是范围界定：按"删掉这一处，这一步还能不能执行"判——删了边界就没了则留，只少一个例子则移。裁决连同理由写进收口表，同一处下次再被提，直接引用这条判决。
12. **自己的怀疑也要判档。** 简报里的疑点常被反证：写"例子太具体会让模型只盯那几类"，两方都说不是——原文里本来就有这个例子、装与不装都误用了它，问题在规则没被执行。把自己的每条怀疑标成成立／部分成立／无证据；被驳的当场认，这才让下一条可信。
13. **落成一张判定表**，在评审目录写 `review_closeout.md`，逐条一行：`# ｜ 谁提 ｜ 意见（一句）｜ 采纳／打折扣／不成立 ｜ 落到哪一页哪一句`。每条"不成立"都带依据——实测输出、快照行号、平台限制——这一栏是给读者复核的。再加一句统计（"共 N 条，采纳 x／打折扣 y／不成立 z"）写进**被改文档自己的变更记录**：以后要证明"这版评审过"，看文档就能对上，不用翻几十 MB 原始输出。没采纳但值得拍板的单列一条，写清代价，不替人定。原始输出原样留档；给读者的汇报是**先结论（选哪个、为什么），再各方挖到的坑（每条一句），最后修正后的落地清单**，不把意见原文贴回去。

## 必查项

发出前：

- **对方能不能看到事实？** 本机文件要真给（复制进评审目录并允许读）；数据库／云文档的题必须**导只读快照（表结构＋记录）**进评审目录。只发自己写的摘要，它只能检验你的叙述、验不了事实，等于没评审。汇报里写清对方读了哪些原始文件／快照。
- **真实文件清单在不在？** `git ls-files` 或 `find . -type f`，它才能核对文中提到的名字／路径是否真存在。最值钱的一类意见就是"你文里写的名字和实际目录不一致"——少一个后缀，读者照着找就找不到。
- **要不要到文件＋行号？** 简报里一句"指到具体那一行"，回来的意见就带 `doc.zh-CN.md:24-27`，可核；没有行号的批评当参考、不当依据。
- **每一份候选都点名了吗？** 超过 10 份时它只读简报点过名的，其余靠推断，然后自述"这几份我没读"。每份写一行：文件名＋行数＋讲什么，并要求"全部读完再答"。回来先查它引用了哪些文件（`grep -oE '[A-Za-z0-9._-]+\.md:[0-9-]+' review_a.txt | cut -d: -f1 | sort -u`），没被引用的＝没看，要么补问一轮，要么标**未评**自己补查。
- **它的覆盖边界原样进表了吗？** "这两份未读、以下是推断"就写"未评（推断）"，别模糊成"建议不发"。把"未评"当成"已评审"、据此砍掉本该发的那一份，是这里最坏的结局。
- **差异测得出吗？** 一问一答测不出差异（强模型在短材料上本来就答对），要用三步真实串联的任务链。判分表每项 0/1、能对着原文判，禁止"质量好"这类空话。**形态差异**（长度、结构）和**正确率差异**分开记：只差 1 分不等于没用，输出变长也不等于好。

收到后：

- **它报的"缺陷"先自证再判定。** "字段／条目不存在"先 grep 快照；"某项没核验"用命令或 API 直接查一次（`git log`、`git grep`、那个端点）；"文件乱码"两边都按 UTF-8 解码查 `\ufffd`——它走控制台读中文会在自己那边花屏，然后把花屏当成被审对象的缺陷报回来。**平台能力断言一律按不成立处理**，除非自己验过（"这个字段删了 N 天内可撤销""这个接口一定读不到 X"），这类话多半是按别的产品推的。查不到就按最坏情况设计操作——先备绝、分小批、每批读回——并在表里写"不成立，依据：未找到该机制"。照抄这类断言，等于让人在不可逆操作上放下戒心。
- **外部事实自己核。** 清单是否活跃、平台限制、规则细节，它说"不确定"时接受这份诚实、自己去查；它编了具体清单名或数字，整条作废，不进汇报。
- **数字类批评先复算再辩。** "你写的 50 个字符实际是 53"多半它是对的，错在我上一轮的脚本或手数。成立就三处一起改：改文件、改文档里那句数字声明、在变更记录里认一句——只改文件下一轮还会被抓。
- **它建议"加证据／加 demo"时，先自己做一次最小实验。** 做得出差异就写；做不出就如实说为什么不做。为满足建议而造一个证明不了东西的对比，发出去会被拆。
- **写操作不给对方。** 它是参谋；写由自己做，并且每次读完验证。
- **敏感值不进简报。** 不带真实金额、客户名、合同号；简报写成"结构＋数字形态"，敏感值用占位。
- **它的"已完成"不算事实。** "文件已写好"看 `ls -la`，"已核对数字"自己重算，"看过哪些文件"以自己实读为准。

## 示例

只作示意——两条命令是能跑的两种形状，其他同类 CLI 换参数。

```bash
# 评审器 A：前台跑，返回干净，1~3 分钟，需放开读文件权限
claude -p '<指令>' --allowedTools "Read"

# 评审器 B：后台 + PTY，目录必须是 git 仓库，只读沙箱
cd <dir> && git init -q 2>/dev/null; codex exec -s read-only '<指令>' > review_b.txt 2>&1

# 指令形状——一句话，三个要求
先用 Read 工具读完当前目录 briefing.md 全文，再严格按第七节的格式答：
四段，每段不超过 8 行。不要重写方案，只挑毛病。
```

简报"现象"一节的四种写法，跨行业、带实测数字：

- 贸易：一次改价要在 4 个地方录入；上周报出的 9 张单里有 2 张带着旧价。
- 物流：送货单与仓单在 340 箱里有 12 箱对不上，靠人眼发现，没有任何检查抓到。
- CRM：一次客户改名留下 3 处旧引用，月报仍按旧名分组。
- 零售：同一个商品挂着 2 个编码，51 行库存里有 7 行用的是拣货端不认的那个。

收口表的三行，含"打折扣"和"不成立"长什么样：

| # | 谁提 | 意见 | 判定 | 落到哪里 |
|---|---|---|---|---|
| 3 | A | 全文正则抽数字当控制总数 | 打折扣：会把叙述里的数字全算进去，淹没告警 | 核验页 §2；断言只对 4 个已知字段 |
| 7 | A + B | 先做一致性体检，别急着自动化 | 成立：两方独立撞到 | 排在落地清单第一条 |
| 9 | B | 这个字段 7 天内可撤销 | 不成立：文档与接口里都没有该机制 | 按不可逆处理；先全量备份 |

## 坑

- **启动日志里的红字不是失败。** 先是缺一个 shell 补全文件，再来 `ERROR: Reconnecting... 2/5 … 5/5` 和 `warning: Falling back from WebSockets to HTTPS transport`，最后仍正常作答。别据此判死，也别重启。
- **答案是打印两遍的**（正文一份、末尾汇总一份）。落文件后取最后一份，别当成它答了两次。
- **走 Windows 控制台读中文会花屏**（`20+ ?` 之类）。它仍读得懂：不要据此判简报坏了，也不要为它改编码。
- **别用 `| tail -N` 接输出。** 管道缓冲到进程结束才吐，中间只看得到启动噪声，会误判"卡住了"。直接 `> out.txt`，用进程状态查进度。
- **后台那个放前台跑会挂死**，报 `pty requires background=true`；它只在 git 仓库里工作，只读沙箱是它不写文件的原因。
- **启动垫片会吞掉指令。** 先让二进制回一句指定的话；回的不是那句，说明位置参数被丢了、回来的是罐头答复。退路是把指令用管道喂进 stdin。
- **中文长指令直接在 shell 里传。** 不要用 Python `subprocess` 拼：Windows 上 `.cmd` 垫片加上编码是双重雷。
- **它写的脚本会引用没跑过的参数**（`--tools ""`、`--system-prompt`）。先查 help 输出，再单条试跑一次。
- **它猜相对路径经常错一层**——五份输入一个没进去，跑出来一半是"读不到文件"却在装没事。先 `ls` 确认产物存在再信这次运行。

## 自检

- 判定表每条都有档，每条"不成立"都带读者能复现的依据。
- 引用过的路径与行号都核过；未评的候选都标出来了，没有沉默带过。
- 三档统计那句话已写进被改文档自己的变更记录。
- 汇报里没有贴意见原文——只有结论、坑、落地清单。
- 没有让评审器写任何东西，自己的每次写都读回验证过。
